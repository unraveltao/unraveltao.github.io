最近，我又开始折腾自己的博客了。说起来，这已经不是我第一次做博客了。

前段时间整理 GitHub 仓库的时候，我重新翻到了一个以前的项目。看着那些熟悉又有些陌生的文件，我突然想起来：原来我在两年前，就已经尝试过做一个属于自己的博客了。那时候是 2024 年。

## 第一次尝试

我最开始接触编程的时候，就挺喜欢这种不断学习、不断探索的感觉。计算机技术有很多有意思的地方。学会一点东西之后，总会发现后面还有更多值得研究的知识。一个框架为什么要这样设计？一段代码为什么能够运行？不同的技术又是怎样组合起来的？我很喜欢琢磨这些问题。

而且，编程还有一个特别吸引我的地方：它能让我把脑子里的想法变成真正可以使用的东西。所以，那时候我就隐约觉得，编程可能会成为自己以后长期走下去的一条主线。做个人博客，就是我早期的一个尝试。

当时我看过一些 YouTube 教程，也尝试过根据别人的项目修改代码。但真正准备做博客的时候，我还是想自己从头搭建。倒不是觉得别人的模板不好。更多是因为，那时候的我看不懂很多现成项目的代码，也不知道以后应该怎样修改、扩展。与其拿一个不太理解的项目继续折腾，我更愿意从最基础的地方开始，一点点弄明白它是怎样工作的。

于是，我开始阅读 Next.js 的官方文档，学习 React、Tailwind CSS，尝试把它们组合起来。那时候的 AI 还不像现在这样强大。我更多是让它帮我解释文档、理解代码，或者生成一些小的代码片段。然后自己再慢慢复制、粘贴、修改，遇到 Bug 就继续研究。

很多时候，做一个功能需要折腾很久。但最后，我确实拼凑出了一个简陋的博客。它有一些基础页面，也能够承载文章。虽然离我想象中的样子还有很大距离，但那毕竟是我自己一步步尝试出来的东西。

我还给它留下了一篇文章。名字很简单：<b>Hello World。</b>

只是后来，这个博客并没有真正完成。我花了不少时间搭建网站，却没有写下多少文章。页面和功能还有很多没完善的地方，项目也就这样慢慢停了下来。

## 后来，我放下了编程

接下来有很长一段时间，我没有再认真推进这些项目。那段时间，我玩游戏，也做过其他事情。回头想想，可能多少有一点逃避生活的感觉。以前尝试过的很多项目，也没有继续维护。

其实我发现自己有一个问题：经常对某件事情产生兴趣，投入不少时间，最后却没能真正坚持下去。编程也是这样。

以前为了做一个东西，我可能需要花很多时间研究文档、理解代码、修复问题。但折腾了很久，最终能够展示出来的成果却很有限。有时候，投入和成果之间的距离实在太远了。慢慢地，我也就把它放下了。

不过现在回头看，我觉得自己可能并没有真正失去对编程的兴趣。我依然喜欢学习新的东西，喜欢研究技术背后的原理，也喜欢创造东西的感觉。只是那时候，我没有继续走下去。

## 重新开始

到了 2026 年 10 月左右，我又开始接触编程了。这一次，最大的不同是 AI。

以前，我需要自己研究怎样写出每一段代码，再慢慢把它们拼接起来。现在，我可以先告诉 AI 自己想做什么，再通过不断交流，让它帮我实现。有时候，只需要描述一个想法，很快就能看到一个能够运行的程序，甚至是一个界面相当精美的应用。

这种感觉和以前太不一样了。以前可能花了很久都做不出多少东西，现在却能很快看到自己的想法变成现实。我重新感受到了创造东西的乐趣。

当然，这不代表 AI 能够自动解决所有问题。很多时候，我仍然需要思考需求、判断方案、检查结果，也需要继续学习那些自己不理解的知识。但至少，我不再需要把大部分精力都耗费在最初的实现过程上。

我开始做一些新的项目，也重新使用 GitHub 管理自己的代码。其中包括我正在开发的 Lattice，一个桌面 Agent 与插件平台。

在重新开发这些项目的过程中，我也开始重新思考一件事情：到底什么才算是自己的创造？

## 我对创造的理解变了

两年前，我更倾向于从零开始做项目。当时，我觉得这样才能真正理解一个东西，也更方便以后修改。

但现在，我的想法发生了一些变化。如果别人已经做出了一个很好的东西，为什么不能拿来学习、修改，再让它适合自己的需求？为什么所有东西都必须从零开始？

以前我可能会很在意一个项目是不是自己亲手写出来的，现在我更在意它能不能真正实现我的想法，以及我能不能理解、控制和改进它。我开始接受使用现成的框架、组件、开源项目，也开始习惯让 AI 参与大量实际开发工作。

这并不意味着我不想学习代码了。恰恰相反，我现在依然很喜欢研究技术原理，只是慢慢意识到，学习和创造不一定要以重复实现所有东西为前提。

我有时候会把这种方式理解成一种“炼化”。把已经存在的知识、技术和工具拿过来，理解它们，吸收它们，再根据自己的想法进行组合和改造。

AI 也是其中的一种工具。它可以帮助我完成很多以前需要花大量时间才能做完的工作，但最终想做什么、为什么要做、是否符合我的预期，仍然需要我自己去判断。

我不再那么执着于每一行代码都必须亲手写出来。对我来说，创造的意义已经不完全是编写代码本身，而是把自己的想法真正实现出来。

## 整理过去的那些项目

重新开始编程之后，我也整理了一遍以前的 GitHub 仓库。翻看那些旧项目的时候，还是有些怀念的。有些项目是跟着教程做出来的，有些是拿别人的代码修改的，还有一些是当时自己一点点研究出来的。看着它们，我会突然想起来：原来我以前还做过这个东西啊。

尤其是重新看到那个旧博客的时候。我甚至有点惊讶，原来自己两年前就已经尝试过做博客了。虽然它很简陋，也没有真正完成，但那确实是我曾经认真投入过时间的一个项目。

不过，怀念归怀念，我也开始删除一些不再需要的仓库。有些项目已经完成了当时的学习目的，有些东西虽然曾经觉得很有意思，但现在已经没有继续维护的必要。

我觉得这有点像使用 Git 开发软件。一个项目可能会有很多分支。有些分支尝试了新的功能，有些分支探索了不同的实现方式。它们可能都有值得保留的想法，但不是所有分支都适合合并进主分支。有时候，我们需要舍弃一些东西，才能继续向前推进。

我觉得自己的经历也有一点像这样。过去做过的那些项目、尝试过的技术、走过的不同方向，都曾经有它们的价值。但它们不一定都需要一直保留下来。

删除一些旧项目，并不代表我要否定过去的自己。只是我觉得，是时候好好整理一下，为接下来的阶段腾出一些空间了。

当然，有些东西还是值得留下。比如那篇《Hello World》。它或许没什么技术价值，甚至当时都没有真正显示在博客里，但它记录了我第一次尝试做个人博客的经历。所以这一次，我想把它留下来。

## 又回到了博客

重新开始编程，做了一些新的项目之后，我又想起了那个一直没完成的博客。我想，这一次应该可以把它做得更好了。于是，我开始重新制作博客，也尝试使用 Astro 来重新组织网站。

不过，这一次我对博客的想法和两年前有些不同。以前，我更多是在折腾怎样把网站做出来。页面应该怎么写？组件应该怎么组织？使用什么框架？怎样把功能实现出来？我花了很多时间研究这些问题，却没有真正写下多少东西。

现在我觉得，自己可能把重点放错了。博客最重要的，或许并不是它使用了什么技术，也不是界面有多么精美。而是我究竟在这里留下了什么。所以这次，我想把文章作为博客的核心。

UI 可以慢慢调整，技术框架以后也可能继续变化。毕竟我喜欢研究新技术，说不定哪天又想把网站重新折腾一遍。但我不希望每次重构网站，都要把过去的内容重新折腾一遍。

我想先建立一个相对稳定的文章结构，认真开始记录自己的经历、学习和思考。那些关于技术的探索、项目开发过程中遇到的问题、突然产生的想法，以及后来对某些事情理解发生的变化，我都希望能够慢慢记录下来。

不一定每篇文章都要有多么深刻的观点。也不一定每次都能得出一个明确的结论。有些东西，只是当时真实的想法。但我觉得，能够把它们留下来，本身就很有意义。

## Hello World，再一次

回头看这两年的经历，还挺有意思的。2024 年，我尝试做一个博客，却把大部分时间花在了搭建网站上。后来，我放下了编程，也放下了那个没完成的项目。到了 2026 年，我重新开始学习和开发，借助 AI 找回了创造东西的乐趣，也开始用不同的方式理解技术和创造。

兜兜转转，我又回到了博客。但这一次，我想做的不只是一个能够展示文章的网站。我更希望它能够成为一个长期记录自己的地方。记录我正在学习什么、创造什么、思考什么，也记录那些尚未解决的问题，以及以后可能发生的改变。

我不知道这个博客最终会变成什么样子。也不能保证以后不会再次重构它。但至少现在，我想认真开始写一些东西了。

网站可以继续修改，项目可以不断迭代，有些旧分支也可以慢慢舍弃。而那些真正值得留下的经历和思考，我希望能够好好保存下来。所以，就从这篇文章重新开始吧。

<b>Hello World。</b>
