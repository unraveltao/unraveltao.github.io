那一次，我差点改变了自己的 Skills 仓库。

在测试过别人的 Skill 之后，我发现，它们的效果比我预想的要好，也比我自己写的一些 Skill 更好。那一刻，我有点动摇：既然别人已经做得这么好了，我还有必要继续做自己的工具吗？

我最终没有改变仓库的方向。但这并不意味着我已经找到了答案。

今天，在整理完 Notion、准备结束对话的时候，AI 又帮我总结了几条管理原则。我原本只是想做一次归档，没想到这些原则反而让我开始重新审视自己最近在做的事情。尤其是最后那句提醒：不要为了建设系统而建设系统。

## 我为什么要造工具？

最开始做 Skill 的时候，我想的是，如果有了这些工具，我应该能减少很多重复的流程。

不过，回头看，当时还有一点别的心思。我觉得自己的仓库里没有多少项目，甚至想过把别人的 Skill 拿过来用，顺便填充一下自己的仓库。

这不完全是出于实际需求。有时候，我只是希望自己有一些东西可以做，有一些东西可以展示。

但我真正想做的，其实是通过创造来学习。就像我想自己写一门编程语言，以此理解编程语言；想尝试写一个操作系统，以此学习操作系统。做 Skill 也是一样。我想知道它是怎么工作的，为什么这样设计，以及怎样才能让它按照我期待的方式工作。

如果目的只是获得一个好用的工具，直接使用别人的成果可能是更好的选择。但如果我也想理解工具背后的东西，亲手做一遍就有了另一种价值。

## 当别人的工具比我的更好

有些测试结果确实让我很受打击。

我设计了一个 README Skill，但它生成的 README 并不好。别人的 Skill 却可以生成更好的内容。有时甚至不使用我设计的 Skill，直接让 AI 做一个 Web UI，效果都比使用我的 Skill 更好。

为什么同样一句话，最后的效果会不一样？差距究竟在哪里？

更让我困惑的是，我甚至不知道自己设计的 Skill 到底有没有被调用。我看到了最终结果，却很难知道背后发生了什么。如果连它是否发挥了作用都无法确定，我又该如何判断自己的设计有没有价值？

这也是我差点改变仓库方向的原因。

但我还是希望这个仓库能够保留一些真正属于自己的 Skill。不是因为别人写的东西不好，而是因为别人的工具未必包含我真正想要的东西。比如，有的工具会直接帮我生成结果，而我有时更希望它先向我提问，和我讨论，让我参与到思考的过程中。

我可以借鉴别人的设计，也可以直接使用更好的工具。只是没有必要因为一次比较，就彻底否定自己正在探索的方向。

## “好欣慰，长大了”

今天有一件很有意思的事情。

我在和自己设计的 Council Designer 交流时，因为还有其他事情要做，就催它快点结束这次对话。

它却说，它反对，因为还有东西没有汇报完。之后，它还提出了一些意见，甚至建议我们再开一个 Council 的小会。

我当时的反应不是生气，而是觉得：它居然会反对我了。

“好欣慰，长大了。”

这就是我当时说的话。

我一直想要的并不是一个只会顺着我的意思做事的 AI。我希望它能够质疑我，在发现问题的时候提出不同意见，而不是因为我是提出需求的人，就默认我的判断一定是对的。

后来聊到 Human-in-the-loop，我发现这正是我想要的协作方式。我希望 AI 能提醒我那些自己没有注意到的问题，但听完它的意见之后，怎么做，还是由我自己决定。

这一次的交流并不能证明我的 Skill 已经足够好，也不能证明它的每一条规则都被执行了。但至少，那次表现符合我真正想要的协作方式。这让我重新意识到，工具的价值不只体现在生成结果的质量上，也体现在它怎样参与我的工作。

## 不要为了建设系统而建设系统

整理 Notion 的过程中，我一直在尝试减少重复的入口、合并相似的内容，把不常用的信息隐藏起来。我希望系统能够越来越简单，可有意思的是，为了追求这种简单，我反而花了越来越多的时间。

一个本来为了节省时间而建立的系统，怎么开始消耗我的时间了？

如果它已经够用了，为什么不先去用它，等真正遇到问题再改呢？

想到这里，我发现自己最近好像又回到了以前那种想到什么就做什么的状态。

我整理 Notion，本来是为了更好地管理知识和项目；我设计 Skill，本来是为了减少重复工作，也为了学习。但做着做着，我会开始研究怎么整理得更好，怎么管理这些工具，怎么让管理工具的工具继续完善。

每一件事看起来都有意义，可真正重要的事情却没有往前走多少。

比如，我最近想学习 Linux，了解服务器和 SSH。但昨天和今天，我几乎没有推进这条学习主线。我去办理了银行卡，又开始处理一些临时想到的事情，还花了不少时间研究软件和配置。

这些事情不是没有价值。有些虽然没有完成，但我已经把研究过的方法记录了下来，以后再接手也会容易一些。

问题在于，为什么一个刚刚冒出来的想法，会突然比我原本已经计划好的事情更重要？

我明明已经有了 Idea Pool，却仍然会绕过它，把新的想法直接提到最前面。似乎只要一个念头足够新鲜，我就很容易忘记自己原本想做什么。

## 让想法先留在那里

我不想压制自己的好奇心。很多值得做的项目，可能就是从一个临时冒出来的想法开始的。

但产生一个想法和立即执行它，应该是两件不同的事。

我希望以后可以先把它放进 Idea Pool，想清楚它要解决什么问题。如果它已经比较成熟，或者它确实是推进主线所必需的条件，那就可以把它提上来做。

否则，我可以先去学习一点 Linux，弄懂几个命令，或者实践一次 SSH 连接。哪怕每天只是向前走一点，也比不断准备、不断更换工具，却迟迟没有开始要好。

等主线有了进展，再从 Idea Pool 中挑选几个合适的想法去实践。

我也知道，这不是一个说完就能解决的问题。

也许有一天，我会发现自己已经在 Codex 上花了不少钱，却突然遇到一个更便宜、更高效的工具。到那时，我会后悔吗？

不一定。因为那个更好的工具，也许只是在当时还没有出现在我的眼前。过去的选择不能只用后来才知道的信息来衡量。

我以后大概还是会被新的工具吸引，还是会怀疑自己正在做的事情，也可能再次陷入不断建设系统的状态。我不知道自己能不能每一次都做出合适的取舍。

但我想把这句话留给未来的自己：

我会慢慢往前推主线，不让临时的念头随便插队。
