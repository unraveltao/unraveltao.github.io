# 项目简报

> 这份文件定的是**边界**：为什么做、做什么、明确不做什么、怎么算成功。
> 需求细节在 [02-Product-Requirements.md](./02-Product-Requirements.md)，决策理由在 [06-Decision-Log.md](./06-Decision-Log.md)。
> 最后更新：2026-10-31

## 1. 背景

2024 年建库时用的是 Next.js + Tailwind + shadcn/ui，结果一直停在脚手架状态：首页只有一行 `Hello World`，博客页是空的。2026 年重做成 Astro，旧内容（`hello-world`）作为唯一遗留被搬过来。

真正的动因不是"想写博客"，而是：**手上 `lattice` 这类项目的设计取舍没有地方沉淀**。写在 README 里太挤，写在 Twitter 上会被截断，写进 issue 没人看。需要一个能承载长推理、又不会变成维护负担的地方。

## 2. 目标

| # | 目标 | 可验证的形式 |
|---|---|---|
| G1 | 把项目设计取舍讲清楚，形成可引用的结论 | 每篇 `summary` 就是一个独立成立的结论句 |
| G2 | 让招聘方五分钟内判断技术判断力 | 首页 → 精选 → 一篇代表作，三步内到达 |
| G3 | 维护成本趋近于零 | 无服务端、无数据库、无 CMS；push 即发布 |
| G4 | 让访客一眼看到"做过什么" | `/projects` 用一屏列出项目名、状态、技术栈，点进去能看到取舍 |

## 3. 非目标

**非目标是"有意不做"，不是"以后再说"。** 要加，顺序是：统计 → 搜索 → 评论。

| 明确不做（v1） | 理由 |
|---|---|
| **文章推送 / 自动化** | 那是**另一个项目**：需要浏览器登录态、定时器、失败重试，是常驻进程。本站是纯静态，合并等于加后端（[06 §4](./06-Decision-Log.md)） |
| 四套视觉预设 | 4 篇文章付 4 倍验收成本；`dashboard` 与"零卡片"直接冲突（[ADR-0003](./adr/0003-visual-identity.md)） |
| 全站中英双语 | 0 篇英文内容，先做只会得到空壳路由（[ADR-0008](./adr/0008-chinese-primary-english-metadata.md)） |
| 评论 | 需要后端或第三方，与 G3 直接冲突 |
| 站内搜索 | 文章数 < 30 时，`/posts` 一屏可扫，搜索是负收益 |
| 阅读量统计 | 需要脚本，破坏"0 个 script 请求" |
| 多作者 / 在线后台 | 单人维护，CMS 的协作能力用不上（[ADR-0002](./adr/0002-mdx-in-repo.md)） |
| 邮件订阅 / 全文双语 / 主题定制 | 每一项都要维护一条新链路 |
| 纯入门教程内容 | 拼不过已有生态，也证明不了判断力（[ADR-0001](./adr/0001-blog-positioning.md)） |

## 4. 约束

| 类型 | 约束 | 影响 |
|---|---|---|
| 人力 | 单人维护，无固定排期 | 不能有需要"照看"的东西 |
| 写作预算 | 每篇约 2 小时 | 不追求长文，一个结论就够 |
| 更新频率 | 一年十几篇 | 列表页不需要分页、不需要搜索 |
| 技术 | 无服务端、无数据库 | 搜索/评论只能走第三方或构建期生成 |
| 部署 | GitHub Pages 用户站点 | URL 被仓库名锁死，全站必须带尾斜杠 |
| 范围 | 只做对外展示；推送管线在另一个项目 | 本站不承担"发布到平台"的任何责任，也不为它留接口 |

## 5. 成功标准

**上线门槛：3 篇 Published。** 三篇各有分工：

1. `featured` = `lattice` 架构总览；
2. 一个具体取舍（如 Rust 侧状态机边界）；
3. "为什么我用 Astro + MDX 而不是 Next + CMS"——既是内容，也是对本项目技术选型的对外解释。

**质量门槛**（文章页，移动端 4G 节流）：Lighthouse 四项 ≥ 95，LCP < 1.2s，CLS < 0.02，首屏 JS ≤ 15KB。

**项目展示门槛**：`/projects` 上每个项目都能回答三个问题——它解决什么问题、用了什么技术、现在什么状态。只有名字和链接的项目不算数。

**长期标准**：三个月后仍有新文章。断更是这个项目最大的风险，也是唯一真正会失败的方式。

## 6. 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| **断更** | 高 | 3 篇门槛 + 每篇 2 小时预算 + 不追求长文 |
| 图片体积失控 | 中 | 单图 200KB 上限，构建期检查，超限失败 |
| 视觉逐渐"加东西" | 中 | 设计系统写死"零卡片零阴影"，新增组件必须先改文档 |
| 代理 502 导致无法 push / 部署 | 低 | 部署动作统一在本地执行，CI 只跑构建 |
| 站名一直不定 | 低 | 它是配置项（`src/lib/site.ts`），不阻塞实现 |

## 7. 一句话总结

**用最少的机制，把最难的推理写清楚。** 任何让"写东西"变慢、或让"维护"变重的东西，都不进这个项目。
